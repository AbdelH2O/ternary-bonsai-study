# Recurrent-state perturbation pilot, 2026-09-29

The frozen exploratory run found **no consistent evidence that these small recurrent-state perturbations accumulate more damage over long context than the MLP control**. Every arm answered all 24 paired retrieval questions correctly at both lengths. A later prompt audit found two decisive shortcuts: every target code starts with `R` while every distractor code starts with `D`, and only distractor names have a three-digit suffix. Either question-blind regular expression retrieves the correct answer from all 48 primary prompts. Thus the primary result does **not** test whether the model preserved the queried association through long context. The correct-answer log-probability contrasts were tiny, changed sign between 2% and 3%, and their paired intervals included zero. In the selected natural QA subset, the 2% state arm lost F1 on two Qasper items; at 3%, both perturbed arms improved on the same 2Wiki item.

This is **not a calibrated causal test of the original hypothesis**. The plan required two perturbation strengths that caused small, measurable, *matched* short-context damage. Neither the initial eight-question calibration nor the independent 32-question calibration found them. The [freeze](PRIMARY_FREEZE.json) explicitly designated the equal-delta 2% and 3% pairs as exploratory before held-out scoring. The primary shortcut and accuracy ceiling prevent its zero contrast from resolving smaller effects or ruling out accumulation on harder tasks.

## What ran

The original Bonsai 2 27B `PQ2_0` GGUF and four copy-on-write variants ran one at a time on the RTX 5070 (12,227 MiB) using the Prism CUDA server. Each state arm perturbed `ssm_alpha.weight` and `ssm_beta.weight` across all 48 linear-attention blocks; its MLP counterpart perturbed the same number of effective weights in `ffn_up.weight`. Both used balanced 128-weight groups and the same nominal ±2% or ±3% multiplier. The [patch manifests](variants/) record the exact groups and seed. The original source SHA-256 and every frozen input hash are in [PRIMARY_FREEZE.json](PRIMARY_FREEZE.json). The variant verifier checked tensor metadata, expected values, and every byte outside the selected patch ranges.

The server used 16,384 context tokens, one slot, 99 GPU layers, 512 batch and microbatch, FP16 KV, no vision projector or speculative decoding, and reasoning off. Requests used temperature 0 and seed 20260929. The four-item baseline gate answered correctly; sampled peak VRAM was 8,232 MiB. All five arms completed 48 primary prompts and 40 natural QA prompts, **440 requests total**, with no request errors, OOMs, or time-limit truncation. The largest actual prompt was 14,062 tokens, below the frozen 14,384-token input cap. Inference wall time summed to 470–496 seconds per arm, excluding model load. Per-request responses, scores, token counts, and timings are in [runs](runs/).

The primary set has 24 factual targets, each asked with a roughly 512-token and 12,000-token context. The same question and answer occur at both lengths. The [frozen prompts](prompts/primary.jsonl) span 516–526 and 11,984–12,140 actual chat tokens. For each arm, “additional long loss” is its loss against baseline at long context minus its loss against baseline at short context; the reported contrast subtracts MLP from state. Positive values would support the accumulation hypothesis in a shortcut-free, matched-damage test. Intervals resample the **24 question pairs**, 10,000 times.

**Prompt validity audit:** [build_prompts.py](build_prompts.py) assigns `R...` only to the target and `D...` to every distractor. Searching each prompt for the sole `R[0-9]{2}X[0-9]{3}` code recovers the gold answer in **48/48** cases without reading the question or matching a name. Independently, distractor names end in three digits and the target name does not; a question-blind name-format search also scores **48/48**. The original eight calibration prompts have the same construction flaws (8/8 by code prefix). The independent 32-item calibration v2 does not use these shortcuts, though it is still a small, simple task. The primary accuracy and answer-logprob results below remain valid measurements of these exact prompts, but are weak evidence about recurrent memory.

| Strength | Baseline accuracy, short/long | State accuracy, short/long | MLP accuracy, short/long | State minus MLP additional long accuracy loss | State minus MLP additional long answer NLL, 95% paired interval |
| --- | ---: | ---: | ---: | ---: | ---: |
| 2% | 24/24, 24/24 | 24/24, 24/24 | 24/24, 24/24 | 0 | +0.000023 [−0.000273, +0.000338] |
| 3% | 24/24, 24/24 | 24/24, 24/24 | 24/24, 24/24 | 0 | −0.000255 [−0.000667, +0.000163] |

The answer NLL is the negative log probability of the **generated correct answer tokens**, excluding end-of-sequence. All 240 primary responses exactly matched the answer, and their returned token bytes reconstructed it, so the secondary measure was valid for all 24 pairs per strength. It is conditional on the model emitting the correct answer; the run cannot measure the probability of a target answer when the model chooses a different response. The exact-accuracy bootstrap interval is [0, 0] only because every observed score was identical. See the [2%](runs/contrast-state-d02-vs-mlp-d02.json) and [3%](runs/contrast-state-d03-vs-mlp-d03.json) summaries and [item-level paired table](runs/paired_primary.csv).

## Selected LongBench-E check

The [selection manifest](benchmark/selection_manifest.json) froze 20 `qasper_e` and 20 `2wikimqa_e` IDs before treatment scoring, stratified 7/7/6 across the source length bins per task. Long inputs exceeding the context budget were excluded before selection; retained prompts were untruncated. Scores use the LongBench English QA F1 normalization. These are **selected-subset means**, not full LongBench scores. Intervals resample the 40 selected items.

| Strength | Baseline mean F1 | State mean F1 | MLP mean F1 | State minus MLP mean F1, 95% paired interval |
| --- | ---: | ---: | ---: | ---: |
| 2% | 0.6098 | 0.5787 | 0.6098 | −0.0311 [−0.0822, 0] |
| 3% | 0.6098 | 0.6348 | 0.6348 | 0 [0, 0] |

At 2%, state alone changed two Qasper scores relative to baseline: one from 1.0 to 0.5556, and one from 0.8 to 0 when the response became “unanswerable.” All other item F1 scores matched baseline, including every 2% MLP item. At 3%, both arms changed the same 2Wiki answer from “Adamair” to the gold answer “Fer Corb,” raising its score from 0 to 1; every other item F1 score matched baseline. Thus the 3% zero interval reflects identical **observed item scores**, not certainty about other questions. See the [2%](runs/longbench-state-d02-vs-mlp-d02.json) and [3%](runs/longbench-state-d03-vs-mlp-d03.json) summaries and [item-level paired table](runs/paired_longbench.csv).

## Calibration and interpretation

The first eight short retrieval questions were answered exactly by all candidates. An eight-chunk perplexity calibration was non-monotonic: 3% state increased mean NLL, but 2% and 5% state did not, and even a 10% MLP scale change did not yield a matched positive effect. The independent [513-token calibration set](prompts/calibration_v2.jsonl) gave 30/32 exact-format answers for baseline, state 2%/3%, and MLP 2%/3%; no new failures occurred at either frozen strength. Correct-answer NLL differences were near zero with intervals spanning zero. The [calibration report](CALIBRATION_REPORT.md) gives the full grid.

These observations do not establish that recurrent-state weights are unimportant. The perturbations may be too mild, and equal affected weight counts do not guarantee equal functional impact: the state arm changes rounded BF16 gate-projection weights, while the MLP arm changes FP16 scales on sampled ternary groups. Per linear block, the intervention covers all 491,520 alpha/beta weights but only 491,520 of 89,128,960 `ffn_up` weights (0.55%). The 128-weight perturbation signs were balanced, so their gate effects may partly cancel. The synthetic primary task has two known shortcuts. The LongBench changes were few and did not replicate across strengths. There is no basis to add the plan's 24-question confirmation set: its prerequisite, a viable matched-damage pilot, was not met. A follow-up should make target and distractor records exchangeable, verify that question-blind heuristics fail, calibrate state and control arms against a harder short-context set, and only then freeze longer held-out questions.
