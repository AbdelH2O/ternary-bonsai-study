## Question and current evidence

**Testable claim:** a persistent change to Bonsai 2's recurrent gate weights causes more *additional* predictive or task loss after many intervening tokens than a non-gate perturbation calibrated to similar short-context damage. This is a comparison of permanently changed checkpoints. It does not directly test numerical rounding error accumulating inside the runtime state, nor explain the shipped model's entire gap from full precision Qwen. Gated DeltaNet state updates make a context-dependent effect plausible, but decay, corrective writes, normalization, and the 16 full-attention blocks can damp or bypass it ([Qwen implementation](https://github.com/huggingface/transformers/blob/main/src/transformers/models/qwen3_5/modular_qwen3_5.py), [Gated Delta Networks paper](https://arxiv.org/abs/2412.06464)). Growth with raw prompt length is a hypothesis, not a guaranteed consequence of the architecture.

The [completed exploratory pilot](EXPERIMENT_REPORT.md) ran five arms and 440 requests on a 12 GB RTX 5070 without GPU errors. It cannot decide the claim. Two question-blind rules each solve all 48 synthetic primary prompts: only the target has an `R` code prefix, and only the target name lacks a three-digit suffix. The 2%/3% state and MLP arms did not yield measurable, matched short-context damage. The MLP patch affected only 0.551% of `ffn_up` weights per linear block versus all selected gate weights, so equal changed-weight counts were not equal functional doses. One perturbation seed cannot establish robustness. Read the [calibration report](CALIBRATION_REPORT.md) and [execution notes](EXECUTION.md) for details; do **not** reuse the old primary prompts as a valid retrieval test.

## Agreed first action: validate position-matched teacher-forced scoring

Implement and verify a scorer **before making more variants or running a full matrix**. Use 4–8 coherent natural documents with at least ~12.5K tokens after one tokenization pass. Freeze source URLs or local paths, licenses where relevant, SHA-256 hashes, tokenizer identity, selected target spans, and token IDs before treatment scoring. Start with the original model only:

1. In each document choose one or more fixed target spans of **64–128 token IDs** beginning at absolute token position `p`, with at least 12,288 tokens before `p`. For history lengths near 1,024, 4,096, and 12,288, feed the strictly nested token-ID slices `[p−h:p]` and score **the same target IDs `[p:p+m]`** in all conditions. The first target token must be scored from the last history token; subsequent target tokens use their preceding gold tokens. Keep target document positions, IDs, boundary convention, and formatting identical across histories and arms. Record any BOS or chat-template policy explicitly.
2. Reduce logits immediately to gold-token negative log-likelihood (NLL); retain per-target-token values or an auditable compact record. Avoid full-vocabulary logit files for the full matrix. If the pinned `llama-perplexity --save-all-logits` path is used for a tiny validation fixture, first verify its token alignment and file format by reproducing the stock tool's printed perplexity, and measure disk usage. Implement a minimal sparse scorer if that path cannot guarantee identical target IDs or is too large. **Changing `llama-perplexity -c` alone is invalid:** its aggregate windows score different token positions at different context sizes. Inspect the pinned Prism behavior rather than assuming current upstream behavior.
3. Run the baseline twice on the same fixture. Check next-token alignment, state reset between documents, state persistence across evaluation batches, and equality or a measured numerical tolerance across reruns. Verify that changing batch boundaries does not change the scored token set. Stop and fix the scorer if any identity, reset, or batching check fails. Then run a 4–8-document baseline at the three history lengths under the 16,384-token, one-slot, FP16-KV execution profile.

For each `(document, target span, history length, arm)` save the document/source hash, target position, history and target token-ID hashes, model and patch hashes, scorer revision, token count, per-token or summed gold NLL, timing, backend settings, and errors. The first deliverable is a short **scorer validation report** with a go/no-go decision, not an accumulation result. Natural-text NLL is a sensitive *dose-calibration instrument*; a context slope alone does not prove recurrent memory use.

## Preparation that does not need GPU inference

Generate and audit the new prompts with ordinary CPU scripts while the GPU scorer is being built. This means text generation, tokenization, hash checks, and simple question-blind heuristics—not running Bonsai inference on CPU. Rebuild the behavioral task in new files without altering the frozen old prompts. Make target and distractor records exchangeable: identical name and code formats, independently sampled codes, no answer derived from an index or prefix, and target selection after record generation. For each registry, ask at least two questions with different answers; swap two values and verify the gold answer follows the swap. Audit question-blind, context-blind, first/last-record, prefix, and formatting heuristics; they should be near chance.

Construct short-near (~1K tokens), long-near (~12K), and long-far (~12K) cases using the actual GGUF chat template for token counts. Keep total length and candidate-record count matched between long-near and long-far, and move neutral filler before or after the target so the **target-to-question distance** changes. Vary distractor count later as a separate interference factor. Freeze prompts, answers, item IDs, and hashes before treatment scoring. The baseline model's response to question/value swaps, baseline accuracy, perturbation effects, and all final scores require GPU inference. Do not start its full GPU matrix until the scorer and perturbation doses pass validation. A null *average* natural-text slope does not by itself veto a small, validated retrieval pilot: rare memory failures can be diluted in average loss.

## After scorer validation: perturbation calibration, then held-out tests

Keep the original GGUF read-only and build reflink variants with manifests and byte-level verification as in [make_variants.py](make_variants.py). Separate `ssm_alpha` and `ssm_beta` rather than changing both at once. Sweep strengths on **calibration documents distinct from held-out documents**. Sweep MLP coverage and strength independently until it produces a modest, measurable, similar short-history excess gold NLL; equal delta or changed-weight count is not matching. Use at least three perturbation sign seeds for random interventions, and record realized values after BF16/FP16 rounding. Baseline reruns define the numerical noise floor. A coherent F32 `ssm_a` decay change can serve as a positive-control stress test, but it is a different intervention from the original BF16 gate-projection claim; confirm the pinned Prism graph interprets `ssm_a` as `−exp(A_log)` before using it ([llama.cpp graph](https://github.com/ggml-org/llama.cpp/blob/master/src/models/qwen35.cpp)).

Freeze doses, seeds, documents, prompt families, scoring code, and a smallest meaningful effect before a larger run. On natural text, compare **state minus MLP additional NLL** at longer versus shorter histories using the *same target tokens*. On the corrected behavioral task, compare the state-minus-control **far-minus-near** loss at equal total length, with accuracy for every response; only use gold-answer likelihood if it can also score wrong responses. Bootstrap document or registry families and account for perturbation-seed variation. Do not call a positive behavioral contrast proof of recurrent-state accumulation: MLP changes can flow into later recurrent blocks and full-attention blocks may carry retrieval. Direct capture or selective restoration of recurrent state is the follow-up needed for a stronger mechanism claim.

**Go to calibration:** scorer alignment and state checks pass, and baseline reruns establish a reliable floor. **Go to held-out testing:** at least one modest state dose and one MLP control show reproducible, matchable short-history damage without making the model unusable; the new retrieval task passes shortcut and counterfactual audits. **Stop and report:** scored token IDs differ across conditions, batching changes the result materially, baseline is at floor, perturbation effects remain indistinguishable from rerun variation, or matching requires severe damage. Failure to match short-context damage limits the intended comparison; it does not alone falsify a long-specific effect.
