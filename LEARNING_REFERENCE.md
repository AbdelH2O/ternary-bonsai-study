# Bonsai 2 Learning Materials Source Brief

**Use:** This is a source brief for creating learning materials, not a student handout. The intended learner is a computer science undergraduate who knows basic arrays, functions, and probability but has little machine learning experience. It collects the concepts, methods, terminology, worked examples, results, and claim boundaries used in the Bonsai 2 investigation. A lesson writer can choose a subset and change the presentation, but should preserve the distinctions below. Linked reports are the sources for exact inputs, code, and raw scores.

The question is whether changes to the model's recurrent *gate weights* cause especially large damage when useful information is far back in the input. The completed studies validated several ways to measure this, but did **not** establish that gate damage accumulates with distance or explains the shipped model's quality gap. The most recent assay found a small recurrent-state signal **after** a retrieval question and almost none when the state was swapped **before** that question. This points toward information being retrieved by attention and then written into recurrent state during question processing; that explanation remains an inference. See the [latest result](remote_components/COMPONENT_REPORT.md).

The teaching material should mark three kinds of statements explicitly: **measured** (a score or identity check in a completed run), **inferred** (a proposed explanation compatible with measurements), and **proposed** (a future assay that has not run). The numeric toy examples in this brief are illustrative unless linked to a result table. The most important conceptual boundaries are weight versus runtime state, predictive loss versus retrieval success, and an intervention's measured effect versus its internal cause.

| Content group | Terms the material should cover | Core teaching point |
|---|---|---|
| Model representation | token, checkpoint, GGUF, quantization, BF16/F16/F32, block, MLP | Stored weights and temporary state are different objects. |
| Information paths | full attention, KV, recurrent block, Gated DeltaNet, gate, R, S | An old fact can reach an answer through more than one path. |
| Measurement | logits, softmax, teacher forcing, NLL, perplexity, answer margin, accuracy | Every metric asks a specific question and has a defined denominator. |
| Experimental design | perturbation, dose, control, seed, calibration, held-out set, freeze | A fair comparison requires matched inputs and choices fixed before evaluation. |
| State methods | capture, import, roundtrip, A–B–A, donor, receiver, position, splice | Technical identity and source mapping come before interpretation. |
| Inference | estimand, interaction, cluster, interval, power, support, exclusion | Thousands of token scores can still represent only a few independent cases. |

## The model and its possible information paths

A **language model** assigns probabilities to the next token given previous tokens. A *token* is a vocabulary ID representing a piece of text, not necessarily a whole word. A **checkpoint** is a saved set of numerical parameters, often called *weights*. During an input, the model also maintains temporary **runtime state**. Weights persist across prompts; runtime state is rebuilt from the current prompt. Confusing the two leads to incorrect claims about what an experiment changed.

The **original** compact checkpoint is the **baseline** for these controlled comparisons. A **variant** is a copy with a specified weight patch. “Original” here means the downloaded Bonsai 2 checkpoint, not the full-precision Qwen model from which it was developed. A **prompt** is the input text presented to the model; a **prefix** is the portion processed before a chosen scoring or capture boundary; a **continuation** is the fixed or generated text after it.

The local Bonsai 2 checkpoint is a compact 27-billion-parameter model in **GGUF**, a file format that stores weights, tensor metadata, and tokenizer information. Its 64 language blocks repeat three recurrent or “linear attention” blocks followed by one full-attention block: 48 recurrent blocks and 16 full-attention blocks. A *block* transforms the current token's vector representation. A **full-attention** block can look back at earlier token representations stored in its **key/value cache (KV cache)**. A **recurrent** block updates a fixed-size state as tokens arrive. The model can therefore use more than one path to recover an old fact. The [structural analysis](README.md) documents the local checkpoint; it is a storage map, not proof that a region causes a behavior.

The recurrent path has two serialized pieces in these experiments:

| Symbol | Plain-language meaning | Why it matters |
|---|---|---|
| **R** | A short convolution buffer holding recent inputs to a recurrent block | It directly spans only a few recent tokens, but higher-layer R can reflect earlier attention or recurrent processing. |
| **S** | The Gated DeltaNet recurrent state | It can carry a compressed summary across tokens. A changed S at the answer does not tell us *when* the information entered it. |
| **KV** | The full-attention key/value cache | It can supply an old value to the question even if recurrent S did not retain it throughout the filler. |

In the pinned runtime, the recurrent R/S cache is stored as **F32** values and the full-attention KV cache used in these runs is **F16**. The studied `ssm_alpha.weight` and `ssm_beta.weight` checkpoint tensors are **BF16**. These are different facts: changing BF16 weights is a permanent checkpoint intervention; it is not a test of F32 runtime rounding accumulating at every step. F32, F16, and BF16 are floating-point formats with different precision and storage costs.

**Gated DeltaNet (GDN)** is the recurrent computation in the 48 linear blocks. Its `ssm_alpha` projection helps set an input-dependent decay or retention gate; `ssm_beta` helps set update strength. The pinned graph applies `softplus(alpha + ssm_dt.bias)` and multiplies it by `ssm_a` for the decay gate, while beta passes through a sigmoid. `ssm_a` and `ssm_dt.bias` are separate small F32 tensors. A gate can forget, retain, or update information, but its presence does not imply that errors necessarily grow with prompt length: decay, later writes, normalization, and full attention can change or bypass the effect. The pinned [Prism graph](https://github.com/PrismML-Eng/llama.cpp/blob/842b188/src/models/qwen35.cpp) is the implementation reference.

A **head** is a group of channels with its own attention or recurrent parameters. A **decay horizon** is a rough timescale derived from a fixed decay rate: if a state were multiplied by $e^{g}$ at every step with $g<0$ and received no new input, its magnitude would fall by a factor of $e$ after about $1/|g|$ steps. The real model's gate depends on the input and its state receives new writes, so a calculated zero-input horizon is not a measured fact-retention interval. **Interference** means later inputs alter or compete with information that might otherwise remain useful.

**Quantization** stores some weights with fewer bits. This checkpoint uses packed `PQ2_0` ternary groups for its large matrices and retains selected small tensors at BF16 or F32. Its packed matrices use a rotated basis; decoding the file and accounting for that basis is necessary before comparing stored numbers with ordinary full-precision Qwen weights. The experiments below mostly compare the original compact checkpoint with controlled copies of itself. They do not measure the causal effect of quantization against the full-precision model.

The basis rotation is Hadamard-related in this model. **Hadamard transform** is the name of a structured orthogonal transform used in the storage and activation scheme; it changes coordinates without making a stored coefficient directly comparable to the corresponding unrotated weight. A lesson can use a simple two-dimensional rotation analogy, while noting that the real transform is higher-dimensional.

An **MLP** (multilayer perceptron) is another part of each block that transforms token vectors. Here `ffn_up.weight` was used as a non-gate **control**: if gate and MLP changes cause equal short-context damage, a later difference is more informative than comparing gate damage with an untouched model alone. “Control” does not mean the MLP cannot affect later recurrent state; it can change the inputs to downstream blocks.

## Tokens, logits, and predictive loss

For each possible next token, the model produces a **logit**, an unnormalized score. **Softmax** converts logits into probabilities that sum to one. If the correct next token has probability $q$, its **negative log-likelihood (NLL)** is $-\ln q$, measured in **nats**. Lower NLL is better. For example, $q=0.5$ gives about 0.693 nat; $q=0.1$ gives about 2.303 nats. Mean NLL averages those values over specified target tokens. **Perplexity** is $e^{\text{mean NLL}}$; it is another way to express the same average, not a separate source of evidence.

**Teacher forcing** scores a fixed text continuation by supplying the true previous tokens at every step. It measures the probability the model assigns to that continuation, even if free generation would choose different words. This removes randomness from generation and lets every checkpoint score the *same token IDs*. It does not by itself show that a model can generate the whole answer unaided.

A **tokenizer** converts text to IDs. The model's **chat template** adds role markers and formatting around user text, so tokenizing plain prose is different from tokenizing a chat prompt. **BOS** is a beginning-of-sequence special token; **end-of-turn** is the special token used to close the scored answer here. **Log probability** is the logarithm of a candidate's probability, and the log probability of a whole teacher-forced answer is the sum of its next-token log probabilities. The full answer's tokenization must preserve the frozen prompt-prefix IDs; otherwise even the first scored answer token would be misaligned.

The **context window** is the token capacity configured for a run. **History length** is the number of prior IDs actually supplied for one target span; it need not fill the context window. **Prefill** processes the prompt or history to build runtime state. **Decode** evaluates later tokens one step or batch at a time. A longer prompt and a fact farther from the question are different experimental factors: adding neutral text can increase length without increasing the target's retention interval, depending on where it is inserted.

The natural-text scorer selects an absolute document position $p$, a history length $h$, and $m$ target IDs. It feeds `IDs[p-h:p]` and scores `IDs[p:p+m]`. At $p=30{,}000$, for example, histories of 1,024, 4,096, and 12,288 IDs are **nested suffixes** ending at the same point. The first target is scored from the last history token's logits. To score target 2, the scorer feeds the true target 1, and so on. The target IDs and their absolute positions are identical in all three conditions. This is **position matching**; without it, a change in loss could merely reflect scoring different prose. Plain-document slices used no beginning-of-sequence token, chat template, or retokenization after slicing. The [scorer validation](scorer/VALIDATION_REPORT.md) explains the alignment checks.

The pinned stock `llama-perplexity` tool resets at context-sized chunks and scores only part of each chunk. Changing only its context-size flag therefore changes which token positions contribute to the aggregate. A sparse custom scorer was validated against a small stock-logit fixture and records one gold-token NLL per target rather than huge full-vocabulary logit arrays. **Sparse** here means sparse *output recording*, not a sparse neural network.

**Excess NLL** is a changed checkpoint's mean NLL minus the original checkpoint's mean NLL on the same targets. Positive excess means worse prediction. Natural-text excess NLL is useful for calibrating a perturbation dose, but a slope with history length is not automatically a measurement of a stored fact surviving that many tokens. Additional context can help prediction through attention, recurrent state, or both.

## Retrieval questions and answer margins

A **retrieval task** asks for a fact placed in a prompt, such as the reference code assigned to a named item. A **registry** is one independently generated set of item–code records. The **target** is the record named in the question; **distractors** are other plausible records. **Filler** is intervening text between a remote record and the question. A *short-near* prompt is about 1K tokens; *long-near* and *long-far* prompts are both about 12K but move the queried record relative to the question. Matching their total length helps isolate **target-to-question distance** from raw prompt length.

The original synthetic prompts had **shortcuts**: only the target code had one prefix, and only its name had one format. A question-blind rule could answer all of them, so high accuracy there did not demonstrate retrieval. The corrected prompts made target and distractor formats **exchangeable**. Their **shortcut audit** checked rules such as first/last record, code prefix, name format, and numeric order. A **value swap** exchanges two remote codes while leaving the question and recent suffix unchanged. If the correct answer reverses with the swap, the model is tracking the assigned value rather than a fixed code preference. A **target removal control** deletes the queried record; a large drop in the correct-versus-wrong margin shows that the record matters. These controls establish prompt validity, not which internal path carried the fact. See the [corrected prompt design](NEXT_EXPERIMENT_DESIGN.md) and [answer-margin gate](VALIDATION_GATES_REPORT.md).

**Exact accuracy** counts responses that match the required answer. When every arm is 24/24 or 48/48 correct, accuracy is at a **ceiling**: a weaker preference can go undetected. To see smaller changes, the scorer teacher-forces both the correct (**gold**) and plausible wrong complete answers, using the same chat template and nine-token code-plus-end-of-turn format. The **answer margin** is

$$
M=\log P(\text{gold answer})-\log P(\text{wrong answer})
  =\operatorname{NLL}(\text{wrong})-\operatorname{NLL}(\text{gold}).
$$

If the gold answer has total NLL 2 and the wrong answer has total NLL 3, $M=+1$ nat: gold is preferred. If a state swap changes the margin from 11.00 to 10.75, the **own-minus-counterfactual effect** is +0.25 nat, even though both conditions still prefer gold. Candidate length, end-of-turn policy, token alignment, and both answers' scores matter. Scoring only the generated correct answer cannot reveal a change in wrong-answer likelihood.

Free **generation** selects next tokens according to a decoding rule. The early pilots used temperature zero, which chooses the highest-scoring token at each step, and a fixed request seed; this made their exact-format outcomes reproducible but did not make the prompt task valid. The selected LongBench-E natural-question subset used **answer F1** rather than exact accuracy: after task-specific text normalization, token precision measures how much of the predicted answer matches the reference, token recall measures how much of the reference was recovered, and F1 combines them by their harmonic mean. Its 40 selected examples were not a full LongBench score. F1 answers a different question from teacher-forced gold NLL or a gold-versus-wrong margin.

Keep units attached to every figure. Natural-text excess NLL and its +0.005 threshold are in **nat per target token**. A complete-code answer margin and its +0.5 or +0.1 thresholds are in **nat per answer**. Their thresholds represent different estimands and are not directly interchangeable.

## Weight perturbations and fair comparisons

A **perturbation** is a deliberate numerical change intended to test sensitivity. The experiments copied the original GGUF using a copy-on-write **reflink**, leaving the source read-only, then changed selected tensor bytes and verified that all other bytes were unchanged. A **patch manifest** records exactly which weights or quantized-group scales changed and by how much. A **seed** makes randomized positive/negative signs reproducible; different seeds test whether a conclusion depends on one sign pattern. A nominal “20% perturbation” describes a scale multiplier, not the resulting prediction damage.

The later study changed `ssm_alpha` alone in all 48 recurrent blocks and used a sampled `ffn_up` MLP control. **Coverage** is the fraction of eligible MLP groups selected; **strength** is the scale change applied to selected groups. The beta-only candidate was examined during calibration but was not the held-out alpha arm. The actual BF16 or F16 values after rounding were checked, because requested changes can round away or vary. The changed-weight count and the nominal multiplier are not a functional **dose**. Here dose means observed short-history excess NLL. **Dose matching** asks whether two arms cause similarly sized short-history damage before comparing their additional long-history effects. Matching a mean does not guarantee matching the distribution of damage across texts or tokens.

**Calibration data** help select doses; **held-out data** evaluate frozen choices. Reusing held-out items to adjust strength and calling them held out again would bias the test. **Fresh** documents or registries have not informed a previous dose or hypothesis choice. A **baseline rerun** estimates numerical reproducibility. A **control arm** gives a comparison for nonspecific damage. A **positive control** deliberately creates a change the assay should detect; failure to detect it suggests the assay is insensitive.

The natural-text primary contrast was a **difference of differences**, also called an **interaction**:

$$
I=[L_{\alpha,12K}-L_{\alpha,1K}]
  -[L_{\mathrm{MLP},12K}-L_{\mathrm{MLP},1K}],
$$

where every $L$ averages NLL over the same target IDs. A positive $I$ means alpha has more additional long-history loss than the MLP control *in this scoring setup*. The common original-model term cancels algebraically. This contrast still cannot isolate recurrent-state damage: the modified weights act at every token, and full attention and later readout layers can mediate the result.

## State capture, import, and timing

A **state capture** saves the runtime memory after processing a known prefix. A **full-state** capture includes attention KV and recurrent R/S. A **recurrent-only** or `PARTIAL_ONLY` capture includes R/S and leaves the destination's KV in place on import. The **donor** is the prompt or checkpoint that produced the saved state; the **destination** or **receiver** is the context that continues scoring after import. The destination's weights and KV must be specified: “swap the state” alone is ambiguous.

An **own-state import** puts a prompt's own saved R/S back into its own destination and should reproduce direct scoring. A **counterfactual import** uses the paired value-swapped prompt's R/S. An **A–B–A restoration** scores directly (A), scores after an imported state (B), restores the destination's original full state, then scores A again. If the last A differs, the implementation has leaked state or altered the scorer. A **roundtrip** saves and reloads the same state; its score should also match. An **unrelated-book positive control** checks that the import operation can change the score when a large state change is expected. These are technical validity tests, not evidence for a scientific hypothesis.

State files also contain **cell position metadata**. Importing a short-history state into a long-history context can produce a non-consecutive-position warning. The [original-model memory gate](memory_gate/MEMORY_GATE_REPORT.md) checked a four-byte position rebase: raw and rebased imports produced identical target NLL vectors in that pinned runtime. That check addresses that metadata field in that assay; it does not prove all mixed states are natural. The first answer token may be scored from logits calculated **before** an import, so state-import analyses explicitly exclude target 0 when it cannot have been affected.

An import can create an **off-trajectory** or **hybrid state**: for example, a long-history attention KV beside a short-history R/S, or original weights reading a state built by a changed checkpoint. A difference under that intervention is causal for the constructed hybrid, but need not equal what the intact model would do. **Reciprocal imports** swap donor and receiver in both directions to reveal receiver dependence; they are not an additive decomposition of “state damage” and “readout damage.” **Readout** here means the destination computations that turn the imported state and current input into logits.

In the latest assay, a **component splice** replaced only R payload bytes or only S payload bytes in a serialized state, leaving its header and other component unchanged. The four post-question conditions were own R/S, counterpart R with own S, own R with counterpart S, and counterpart R/S. The **R/S interaction** is the combined margin effect minus the sum of the two one-component effects; reporting it avoids assuming additivity. The same experiment imported combined R/S **before** the question and teacher-forced the question plus answer. A post-question S effect may be a recent record of what attention retrieved while reading the question; it is not necessarily 12K-token retention by S. Pre-question import better tests what was present before the question, though destination KV can still overwrite or mask it while the question is processed. See the [component report](remote_components/COMPONENT_REPORT.md).

**Attention reinjection** is the proposed path in which a full-attention block reads an old record from KV while processing the recent question, then later recurrent blocks write a value-dependent trace into S. The existing timing result is compatible with it, but does not directly observe that write. A future **layer-selective splice** could compare S from early recurrent blocks with S from blocks after a full-attention block. Such a splice has not been run, and a positive late-block effect alone would not identify the exact write step.

## Technical execution and reproducibility

The experiments **pin** a specific Prism llama.cpp release and record hashes of the model, tokenizer, scorer, linked CUDA libraries, input texts, token-ID files, and patches. A **SHA-256 hash** is a byte-level fingerprint: matching hashes are evidence that files did not change between freeze and run. A **freeze** or **preregistration** records inputs, estimands, thresholds, and analysis code *before* treatment results are examined. A **versioned technical amendment** can repair an implementation issue while preserving the failed version and explaining the change. JSONL stores one structured result per line; raw per-token vectors allow independent recomputation. An **artifact inventory** hashes the final outputs. Hashes make an experiment auditable; they do not make its design scientifically valid by themselves.

The common scoring profile used a 16,384-token context, one sequence, CUDA offload, F16 attention KV, flash attention, and logical/physical batch sizes of 512/512. A **logical batch** groups tokens submitted for evaluation; a **physical microbatch** is a smaller unit the backend may execute internally. The scorer checked state reset between documents, persistence across evaluation batches, and exact reruns. Changing physical microbatch 512 to 256 kept token IDs fixed but changed some NLLs, so comparisons require a fixed execution profile and a measured numerical floor. Even moving a capture boundary can change CUDA batching and direct scores. In the latest pre-question run, the largest direct-answer per-token difference from the older post-question profile was 0.0571 nat; import effects were therefore compared **within**, not directly between, those profiles.

On this workstation, the default sandbox hides `/dev/nvidia*`. **Host-device CUDA execution** gives the pinned binary access to the NVIDIA GPU; it is an execution requirement, not a treatment condition. CPU work can tokenize, build prompts, audit shortcuts, parse state files, and hash artifacts without running model inference. Timings, VRAM, load errors, and position warnings are retained because a missing or failed case can bias a result. The [validation report](scorer/VALIDATION_REPORT.md) and [state gate report](VALIDATION_GATES_REPORT.md) show the technical checks.

## Statistical decisions and their limits

An **assay** is one specified measurement procedure, including prompts, scoring, intervention, and analysis. An **estimand** is the exact quantity it aims to estimate. “Does the model remember?” is too broad; “mean own-minus-counterfactual nine-token answer margin across eight registry families” is an estimand. A **smallest meaningful effect** is a threshold chosen before results. A **gate** is a predeclared decision rule. A **support gate** states what estimate, interval, and consistency are required to support a prediction. An **exclusion gate** can say a particular positive effect size is too large to fit the data in this assay. **Unresolved** means neither rule passed. A **go/no-go** decision determines whether evidence warrants the next, more expensive experiment. Excluding a chosen effect is not proof that the true effect is exactly zero or that the mechanism never matters elsewhere.

A **confidence interval** describes uncertainty under its sampling assumptions. The studies used a **cluster bootstrap** that resamples books or registry families, and sometimes perturbation seeds, or a **t interval** over six or eight cluster means. Repeating the bootstrap 20,000 times stabilizes the calculation; it does not create 20,000 independent books. Multiple target tokens from one span, two spans from one book, and base/swap prompts from one registry are correlated. The book or registry is often the **independent unit**. With only four, six, or eight clusters, intervals and leave-one-out sensitivity can be unstable. An interval across books for one fixed perturbation seed also says nothing about variation over possible seeds.

For teaching, distinguish the **confidence procedure** from a probability assigned to the particular result: under its assumptions, a nominal 95% procedure covers a fixed target effect in about 95% of repeated studies. It does not mean the fixed effect has a 95% probability of lying in this computed interval. Small-cluster assumptions can make the actual coverage differ from nominal coverage.

**Power** is the chance a gate would detect a specified true effect. A threshold set near the noise level can yield an inconclusive result even after many scored tokens. **Equivalence** asks whether the whole relevant interval lies inside a prespecified tolerance band. A failed equivalence test does not prove a difference: the interval might overlap the band and extend outside it. **Sensitivity analysis** checks how conclusions change when one book or registry is removed, when early versus late target tokens are examined, or when a different justified interval method is used. These checks qualify a frozen primary decision rather than silently replacing it. **Multiple looks** at the same data can suggest follow-ups but should not be presented as fresh confirmation.

**Post hoc** means chosen after seeing a result; such analyses can reveal mechanisms but cannot inherit a frozen test's error guarantees. **Replication** repeats a fixed question and analysis on genuinely new independent documents, registry families, or perturbation seeds. Repeating the same computation on the same files verifies arithmetic or implementation, which is valuable, but is not new-sample replication.

The distinction between **prediction**, **observation**, and **mechanism** is central. A checkpoint can lose more on long text without its recurrent memory being the cause. A state import can alter answer likelihood without proving that S held a fact throughout the filler. A baseline can answer every question while answer margins still change. Strong mechanistic language requires controls that remove or hold fixed alternative paths.

## What the completed experiments established

| Stage | Main observation | Decision and limit |
|---|---|---|
| [Early perturbation pilot](EXPERIMENT_REPORT.md) | All arms answered the synthetic questions, but a question-blind formatting rule could too. | Prompt shortcut invalidated retrieval interpretation; matched damaging doses were absent. |
| [Position scorer validation](scorer/VALIDATION_REPORT.md) | The same 96 target IDs were scored under nested 1K/4K/12K histories on four books; identities passed. | Go for controlled measurement, not evidence for accumulation. |
| [Dose calibration](dose_calibration/DOSE_CALIBRATION_REPORT.md) | Alpha and MLP arms had similar mean short-history excess NLL on calibration books. | Selected doses for a small pilot; matching did not generalize reliably. |
| [Held-out natural text](heldout_nll/HELDOUT_REPORT.md) | Alpha-minus-MLP long/short interaction was about −0.0005 nat/token; four-book interval crossed +0.005. | No support for extra alpha long-history loss; +0.005 was not excluded and held-out dose matching failed. |
| [Fresh-book state import](fresh_state/FRESH_STATE_REPORT.md) | One-seed alpha-minus-MLP state interaction was about −0.00045 nat/token. | The frozen +0.005 effect was excluded within that six-book assay; dose equivalence was not established. |
| [Original-model memory gate](memory_gate/MEMORY_GATE_REPORT.md) | Longer-built R/S improved the secondary 1–95-token mean with 12K KV fixed. | Primary early-window gate remained unresolved; R/S and attention history were not fully separated. |
| [Remote-value state gate](remote_state_gate/REMOTE_STATE_REPORT.md) | Post-question combined R/S import changed answer margin by +0.249 nat on eight registries. | A smaller positive state effect appeared, but the frozen +0.5-nat effect was excluded. |
| [R/S and timing follow-up](remote_components/COMPONENT_REPORT.md) | Post-question S-only effect was +0.228 nat; pre-question combined effect was +0.006 nat. | Excluded +0.1-nat pre-question effect in this fixed assay; question-time attention reinjection is plausible, not proven. |

The current **go/no-go** is to stop before a broad alpha/MLP perturbation matrix. This is a scope decision based on these assays, not a claim that recurrent memory is never useful or that BF16 gate weights cannot matter.

## Proposed next experiment and vocabulary still to be validated

A possible next study would use **fresh registry families** and ask whether a recurrent state built with a remote fact changes the answer when the destination's *recent suffix and attention information* are held constant. The intent is to prevent old attention KV from retrieving the fact during the question, so any remaining difference is more diagnostic of long-range recurrent retention. **Attention-controlled** is an intended comparison, not a proven property of a particular implementation. This has **not** been implemented, frozen, or run. It requires a technically valid way to align source/destination positions and attention context, an own-state identity, full restoration, a positive sensitivity control, equal candidate IDs, and a predeclared effect threshold before interpreting answer margins. An attention-controlled hybrid can itself be off the model's normal trajectory, so even a positive result would need independent replication and careful interpretation.

If that gate finds a reproducible pre-question S effect on new registries, an alpha-versus-control weight comparison could be designed around it. If it does not, report the assay's detection limit and stop that mechanistic line. Do not reuse the already examined registry families as “fresh” confirmation.

## Suggested order for learning materials

1. **Next-token prediction:** tokenize a sentence, turn example logits into probabilities, and calculate one-token NLL and perplexity.
2. **Fair comparison:** draw nested histories around one fixed target span and show why the target IDs must remain identical.
3. **Retrieval validity:** construct a deliberately shortcut-prone registry, find its question-blind rule, then repair it with exchangeable records and a value swap.
4. **Controls and interventions:** distinguish weights, R/S, and KV; trace what changes in a full-state versus recurrent-only import, including the donor and receiver.
5. **Uncertainty and claims:** calculate one registry's answer margin and a difference of differences, then explain why eight registries give eight independent units rather than hundreds of answer tokens.
6. **Scientific interpretation:** compare post-question and pre-question swaps; identify what the data show, what attention reinjection would predict, and what experiment would test that explanation next.
