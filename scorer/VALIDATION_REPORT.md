# Position-matched teacher-forced scorer validation

**Decision: GO to perturbation dose calibration using the fixed 512/512 execution profile.** The scorer passed token-identity, next-token alignment, rerun, recurrent-state reset, and logical-batch persistence checks. This is a scorer decision only. No new checkpoint variants, dose sweep, or perturbation matrix were run. The earlier frozen primary, calibration-v2, and LongBench selection files still match their SHA-256 values in `PRIMARY_FREEZE.json`; the unrelated `uv.lock` modification was untouched.

The pinned runtime is Prism `prism-b10735-842b188 cuda-13.3`; the baseline GGUF SHA-256 is `3907dc1658db1f78a9826bf8d5bcb8dc65db0d466388937af57f2294fae62ec1`. The [pinned `llama-perplexity` source](https://github.com/PrismML-Eng/llama.cpp/blob/842b188/tools/perplexity/perplexity.cpp) divides input into context-sized chunks, resets state for each chunk, and scores only the last half except its first token. Its aggregate at different `-c` values cannot compare the same targets. `--save-all-logits` writes `_logits_`, three int32 dimensions, chunk token IDs, then quantized log-probability rows. The tiny 64-token/two-chunk audit dump occupied **30,792,708 bytes**. Parsing its saved rows reconstructs the printed PPL 5.1728 as 5.1728009; the sparse scorer gives 5.1728319 on the same 62 gold IDs, with maximum individual NLL difference 0.000122 nat (including saved-row quantization). The saved IDs equal the frozen tokenizer IDs.

The [sparse scorer](position_scorer.cpp) feeds exact IDs. At full-document zero-based position `p=30000`, every run feeds `[p-h:p]` and scores the same 96 IDs `[p:p+96]`, for `h=1024,4096,12288`. Logits from the last history token score target 0; each later gold token scores the next target. No BOS, chat template, or retokenization is applied to these plain-document slices. Each logit vector is reduced to gold NLL immediately. The [frozen manifest](frozen_manifest.json) records URLs, local source paths, Project Gutenberg public-domain status in the US, source and ID hashes, target and history hashes, model/scorer identity, and the boundary policy. All four coherent books have more than 100,000 token IDs; each selected span is well inside prose.

On a two-document, 96-token fixture, two independent 512/512 runs were bitwise equal. A–B–A within one process reproduced A exactly, including after B's recurrent state. A single logical 1,119-token batch and split 512-token logical batches were equal, as were 256- and 512-token logical batches when physical microbatch stayed 256. This checks state persistence across evaluations and reset between documents. Changing the **physical** microbatch from 512 to 256 caused numerical changes: maximum token NLL difference 0.07842 nat, maximum 96-token mean difference 0.000800 nat. Thus the 512/512 profile is frozen for any subsequent arm; a changed microbatch needs its own baseline floor. The fixture's IDs and scored-token count did not change.

The full original-model run scored **4 documents × 3 histories × 96 targets = 1,152 gold IDs** without errors. Backend logs confirm 16,384 context, one sequence, 99 CUDA layers, flash attention on, and f16 K/V. The [enriched JSONL](baseline_results.jsonl) contains each condition's source hash, target position, history/target ID hashes, model/patch/scorer hashes, all 96 gold NLLs, timing, backend settings, and error field. The [validation summary](validation_summary.json) contains check results; raw runs and logs, the tiny stock dump, source texts, and full token-ID files are in this directory. To reproduce on a host with the pinned CUDA binaries and NVIDIA devices, run `bash analysis/bonsai2/scorer/run_validation.sh`. The script rebuilds against pinned Prism headers and verifies the frozen source/model hashes before scoring. No inference should be run through the default sandbox because it hides `/dev/nvidia*`.
